# Oracle Transaction & Flashback Lab

Практическая SQL-лаборатория для изучения **транзакций, изоляции и восстановления данных в Oracle Database**.

Проект помогает не просто прочитать документацию, а **воспроизвести реальные сценарии и увидеть поведение Oracle на практике**: что происходит с данными при параллельных изменениях, как работают точки сохранения и автономные транзакции, а также как найти и восстановить предыдущее состояние данных.

## 🎯 Что вы получите

Используя этот проект, вы сможете:

* понять, как Oracle управляет транзакциями;
* на практике изучить `COMMIT`, `ROLLBACK` и `SAVEPOINT`;
* увидеть работу автономных транзакций через `PRAGMA AUTONOMOUS_TRANSACTION`;
* разобраться с транзакциями только для чтения;
* воспроизвести сценарии параллельной работы нескольких сессий;
* увидеть последствия разных уровней изоляции;
* понять особенности `READ COMMITTED`;
* посмотреть, как получить прошлое состояние данных через Flashback;
* проверить, доступны ли необходимые данные в `UNDO`;
* отработать сценарий восстановления данных к определённому моменту времени.

Это может быть полезно **Oracle-разработчикам, DBA, инженерам и тем, кто изучает SQL и управление транзакциями**.

## 🔬 Что можно изучить

### Транзакции

В `scripts/transactions/` находятся практические примеры:

* **Autonomous Transactions** — независимые транзакции внутри основной транзакции;
* **Read-Only Transactions** — работа с фиксированным состоянием данных;
* **Savepoints** — частичный откат изменений без полного `ROLLBACK`.

### Уровни изоляции

В `scripts/isolation-levels/` можно воспроизвести сценарии с несколькими параллельными сессиями и увидеть:

* как одна транзакция видит изменения другой;
* какие проблемы могут возникать при параллельной работе;
* как ведёт себя Oracle на уровне `READ COMMITTED`;
* почему результат запроса может зависеть от момента выполнения.

### Flashback

В `scripts/flashback/` показано, как работать с предыдущими состояниями данных:

* получать данные «как они выглядели» в прошлом через `AS OF TIMESTAMP`;
* анализировать историю изменений;
* проверять доступность старых версий данных через `UNDO`;
* использовать Flashback для восстановления данных.

## 🚀 Как использовать

### 1. Подготовить тестовые данные

Сначала выполните скрипты из:

```text
scripts/setup/
```

Они создают необходимые таблицы и тестовые данные.

### 2. Изучить транзакции

Перейдите к:

```text
scripts/transactions/
```

Выполняйте сценарии по очереди и наблюдайте, как изменяется состояние данных после `COMMIT`, `ROLLBACK` и `SAVEPOINT`.

### 3. Проверить изоляцию

Для сценариев из:

```text
scripts/isolation-levels/
```

понадобятся две параллельные SQL-сессии.

Это позволяет самостоятельно увидеть, какие данные доступны каждой транзакции во время одновременных изменений.

### 4. Попробовать Flashback

После изменения тестовых данных используйте сценарии из:

```text
scripts/flashback/
```

и попробуйте получить состояние данных на более ранний момент времени.

## 💡 Для чего использовать этот проект

Проект можно использовать как:

* **практикум по Oracle Database**;
* набор экспериментов для изучения транзакций;
* материал для подготовки к техническому собеседованию;
* основу для демонстрации поведения Oracle коллегам или студентам;
* песочницу для проверки гипотез перед реализацией в рабочей базе;
* справочный набор SQL-сценариев при разборе проблем с транзакциями и восстановлением данных.

Главная идея проекта — **дать возможность самостоятельно воспроизвести поведение Oracle**, а не ограничиваться теоретическим описанием.

## ⚠️ Важно

Запускайте сценарии в тестовой базе данных. Скрипты предназначены для обучения и экспериментов и могут изменять или откатывать тестовые данные.

## 🛠 Требования

* Oracle Database;
